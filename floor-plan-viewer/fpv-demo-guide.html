Floor Plan Viewer — How It Works

1. The end-to-end flow

Everything is wired through one file, src/viewer/floorPlanViewer.js — it's the "god module" that owns all state and imports every other module. Nothing else talks to anything else directly; they all report back to this controller through callbacks.

1Upload. User drops an image/PDF/CAD file → uploadDropzone.js detects the type → loads it into the <img id="plan"> element.
2Analyze. User clicks "Analyze" → services/vision.js sends the image to an AI vision model (Kimi / Gemini / local LM Studio) → gets back JSON: rooms, walls, doors, a calibration hint.
3Calibrate. lib/calibration.js converts the AI's guess (or a user-drawn reference line) into real-world mmPerPixel, so every measurement downstream is in actual millimeters.
4Load catalog. services/supabase.js fetches the furniture catalog table from Supabase; lib/catalog.js normalizes messy DB columns into a clean shape; falls back to lib/planFurniturePresets.js if Supabase is unreachable.
5Place furniture. User drags an item from the catalog drawer onto the plan → lib/furnitureItem.js creates it → lib/catalogSizing.js sizes it in real mm → lib/furnitureBounds.js keeps it inside the room polygon → optionally lib/vastuPlacement.js snaps it to the correct Vastu compass zone.
6Render. viewer/planCanvas.js + viewer/furnitureLayer.js draw everything as SVG on top of the plan image, in real time as things move.
7Price it. Every placed item that's added to the "bag" flows into lib/boqExport.js, which builds priced rows (using Supabase price or the lib/catalogPrices.js fallback table) → viewer/billBar.js shows a running total strip.
8Go 3D. Same room/wall/furniture data is handed to viewer/plan3dViewer.js, which extrudes walls, loads real GLB furniture models from Cloudflare R2, and lets the user walk/orbit the space.
9Photoreal. From the 3D view, a screenshot is POSTed to /api/photoreal (a Cloudflare Pages Function) which calls an image-gen model and returns a realistic render.
10Export / share. Download BOQ as PDF/CSV, download a full design deck (PPTX), or generate a share link / publish to the public gallery.

2. Suggested demo script

~5 minute walkthrough

  1. Upload a floor plan image → click Analyze → point out the AI-detected rooms/walls appearing as an overlay.
  2. Draw a calibration line on a known wall (or accept the AI's guess) → mention this is what makes furniture sizes "real mm", not guesses.
  3. Open the catalog drawer → drag a sofa into a room → show it snapping inside the room boundary and let it auto-suggest a Vastu-correct position.
  4. Rotate/replace/duplicate the item using the floating furniture toolbar.
  5. Add 2–3 items to the bag → show the bill bar total updating live → open the full BOQ summary.
  6. Switch to 3D → orbit the room, show the real GLB furniture models and wall extrusion.
  7. Trigger a photoreal render from the 3D view.
  8. Download the BOQ PDF and/or the design deck PPTX.
  9. Generate a share link, open it in a new tab to show the read-only public view.

3. Upload layer

src/upload/uploadDropzone.js

Binds drag-drop and the hidden file input. Sniffs MIME type: image passes straight through, PDF and CAD get routed to the pickers below. Calls back to the controller with a File.

src/upload/pdfImagePicker.js

Renders every page of a dropped PDF to canvas via PDF.js, shows a thumbnail picker modal, returns the chosen page as a PNG data URL — downstream code never knows it came from a PDF.

src/upload/cadImagePicker.js

Rasterizes a CAD/DXF file to a PNG data URL the same way.

4. Vision AI (room detection)

src/services/vision.js

fileToImageBase64() downsizes the image to ≤1920px before sending (keeps API cost/latency down). analyzeFloorPlan() routes to whichever provider is configured — Kimi (Fireworks), Gemini, or a local LM Studio instance proxied through the Flask dev server at /api/analyze.

src/lib/visionPrompt.js

The system prompt — defines the exact JSON schema the model must return (rooms, walls, doors, calibration).

src/lib/jsonRepair.js

AI responses get truncated or malformed sometimes; this patches unclosed brackets/trailing commas before parsing.

src/lib/analysisValidation.js

Validates the repaired JSON actually has the expected shape before the app trusts it.

5. Coordinates & calibration

Everything is stored in normalized 0–1 space relative to the image, not raw pixels — this is what lets zoom/pan/3D all share the same data.

src/lib/coordinates.js

The image uses object-fit:contain, so there are letterbox bars around it. clientToNormalized() accounts for that when converting a mouse click to 0–1 space. normToWorld() converts further into Three.js world coordinates for the 3D view.

src/lib/calibration.js

Turns a calibration line (user-drawn or AI-guessed) into mmPerPixel — the single number that lets furniture sizes be expressed in real millimeters everywhere else in the app.

src/lib/geometry.js

Pure math: pointInPolygon, polygonArea, bounding boxes. Used for room hit-testing and furniture containment. Has a matching Python implementation in app.py kept in lockstep via scripts/geometry.test.mjs + tests/test_geometry.py.

6. Catalog system

src/services/supabase.js

Supabase client singleton. Reads shearling_catalog (anon read-only table) and a projects table for save/share. Also handles uploading plan images to Supabase storage.

src/lib/catalog.js

Adapter: turns messy raw Supabase rows (columns like "Product Code" with spaces) into one canonical CatalogEntry shape. Builds a fast lookup index.

src/lib/catalogSizing.js

Answers "how big is this on the plan?" — writes real-world width/depth onto a furniture item from calibration + catalog data.

src/lib/catalogPrices.js

Hardcoded fallback price table (from the "Shearling Moulded Chair Catalogue 2024-2025"), keyed by product code. Used when a Supabase row has no price — so the bill never shows ₹0 for a known SKU.

src/lib/sofaColors.js

Upholstery color options and parsing of raw catalog color text into selectable color IDs.

src/lib/planFurniturePresets.js

Built-in default catalog used when Supabase is unreachable, so the app still works offline/in a demo with no DB.

7. Furniture lifecycle

A furniture item is a plain object living in data.furniture[] — position, rotation, scale, catalog link, color override, real-world mm dimensions.

src/lib/furnitureItem.js

create() births a new item with defaults. isSofa(), isColorable(), resolveColorId() answer type-specific questions used all over the UI.

src/lib/furnitureBounds.js

Keeps furniture inside its room polygon as it's dragged; clamps and nudges position.

src/lib/wallSnap.js

Snaps an item flush against the nearest wall (for wardrobes, TV units, etc).

src/lib/vastuPlacement.js

Maps furniture type → correct Vastu compass zone within a room → a target position, and resolves overlaps if two items land in the same zone.

src/viewer/roomAutoStage.js

Auto-fills empty rooms with sensible preset furniture (e.g. bedroom gets a bed + wardrobe) so a demo plan doesn't have to be furnished by hand.

src/lib/undoStack.js

Ring-buffer undo/redo, capped at 50 entries.

8. 2D viewer / rendering

src/viewer/planCanvas.js / svgRenderer.js

Draw rooms, walls, and labels as SVG on top of the plan image. svgRenderer is the same logic reused for file export.

src/viewer/furnitureLayer.js, furniture2dRender.js, furnitureShapes.js

Draws every placed furniture item — furnitureShapes.js holds the actual SVG path definitions per furniture type (sofa, bed, table, plant, etc).

src/viewer/richFurnitureIcons.js, glbTopDownBake.js

For catalog items that have a real 3D model, bakes a top-down photorealistic PNG from the GLB (via an offscreen Three.js renderer) and caches it, instead of using a generic icon shape.

src/viewer/realistic2dCanvas.js

An alternate photorealistic 2D textured render mode for the plan.

src/viewer/doorLayer.js, roomOverlay.js, tooltip.js

Door swing arcs, room fill/highlight colors, and hover tooltips showing room name/area.

src/viewer/toolbar.js, catalogDrawer.js, furnitureToolbar.js, furnitureSelection.js

Top toolbar (file/geometry tools), the slide-in catalog panel with search, and the floating per-item action bar (rotate/replace/copy/remove/add-to-bag).

src/viewer/geometryEditor.js, planTools.js, geometryOverlays.js

Manual room/wall drawing and vertex editing when the AI detection needs correcting, plus measurement tools.

9. 3D viewer

src/viewer/plan3dViewer.js

The 3D orchestrator — sets up the Three.js scene and animation loop, ties together every module below.

plan3dElevation.js, plan3dGlb.js, plan3dMaterials.js, plan3dLighting.js, plan3dEnvironment.js

Extrudes 2D walls into 3D meshes; loads .glb furniture models from Cloudflare R2; sets up PBR materials (fabric/wood/glass/floor), lighting, and an HDRI environment for reflections.

plan3dCamera.js, plan3dInteraction.js, plan3dMove.js

Camera fly-to/orbit/minimap; click-to-select furniture and rooms via raycasting; drag furniture across the floor plane.

plan3dWallPaint.js, plan3dMeasure.js, plan3dMeasureOverlay.js

Wall color picker in 3D, and a tape-measure tool (click two points → real-world distance, shown as a CSS overlay on the WebGL canvas).

plan3dSnapshot.js

Captures a screenshot of the current 3D view and POSTs it to /api/photoreal to get back an AI-generated realistic render. In local dev this endpoint doesn't exist unless VITE_PHOTOREAL_URL is set — the Flask route was deliberately removed so there's a single implementation, the Cloudflare Pages Function.

10. Pricing, BOQ, deck export

src/lib/boqExport.js

buildBoqRows() turns bagged furniture into priced rows (qty, dims, unit price, GST); downloadBoqPdf() / downloadBoqCsv() export it.

src/viewer/billBar.js

The IKEA-style running total strip, expandable into a full cost summary panel.

src/lib/deckExport.js

Builds a full design-deck PPTX client-side (using pptxgenjs) — no server round-trip needed.

src/lib/planThumbnail.js

Captures the current plan as a thumbnail image, used for save/share previews and the gallery.

11. Save / share / gallery

src/services/projectShare.js

Save/load/publish a project via the Supabase projects table.

src/lib/shareLink.js

generateShareToken(), buildShareUrl(), parseViewToken() — the share-URL scheme.

src/viewer/shareControls.js

Share-link and Publish buttons in the toolbar, including WhatsApp share.

src/gallery/main.js, gallery.html

The public gallery page — lists published designs as cards.

src/manufacturer/main.js, portal.js, manufacturer.html

Admin portal for manufacturers to upload catalog photos and edit SKU rows (via services/skuAdmin.js).

12. Servers & deployment

FileRole
app.pyFlask dev server — serves the built app, proxies /api/analyze to Kimi/Gemini/LM Studio, and handles project save/load + dataset export routes. No longer hosts photoreal or deck-export routes.
server.mjsLightweight Node alternative — just proxies /api/analyze to a local LM Studio instance.
vite.config.jsMulti-page build: index.html, manufacturer.html, gallery.html each get their own bundle.
wrangler.tomlCloudflare Pages config, project name planr. Binds an R2 bucket (sofa-3d) as RENDER_BUCKET for storing photoreal renders.
functions/api/photoreal.jsThe live Cloudflare Pages Function — the single, production implementation of the photoreal endpoint.

14. Known gaps to be aware of

Uncommitted work in progress: your git status shows uncommitted changes to package.json, scripts/compress-glb.mjs, plan3dGlb.js, plan3dViewer.js, and roomAutoStage.js, plus untracked .wrangler/, an R2 backup folder, a new scripts/.verify-perf.mjs, and several .verify-*.png screenshots left over from local verification runs. None of that is reflected above since it's not yet committed — worth deciding before a demo whether those changes should be merged in or the working tree cleaned up.
No dedicated test for BOQ pricing fallback: catalogPrices.js has no matching *.test.mjs the way most other lib/ files do — if you change that price table, nothing will catch a regression automatically.
