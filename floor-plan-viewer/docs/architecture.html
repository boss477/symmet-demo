System Overview

A browser-based interior design tool. User uploads a floor plan image → AI detects rooms → user places furniture from a catalog → app generates a live invoice → exports to PDF or 3D render.

Architecture Layers

Each layer has strict rules about what it can touch. This prevents spaghetti and keeps lib/ testable headlessly.

Upload Layer — File Ingestion
uploadDropzone.js pdfImagePicker.js cadImagePicker.js

Can use: DOM, FileReader, PDF.js canvas. Cannot touch: Supabase, Three.js, data state directly.

Vision AI Layer — External AI Calls
services/vision.js lib/visionPrompt.js lib/jsonRepair.js lib/analysisValidation.js

Can use: fetch, FileReader, canvas for resize. Cannot touch: DOM elements, Supabase directly.

Pure Logic Layer — lib/ (headlessly testable)
geometry.js calibration.js coordinates.js furnitureItem.js catalog.js catalogSizing.js sofaColors.js vastuPlacement.js furnitureBounds.js wallSnap.js planMoat.js boqExport.js shareLink.js undoStack.js

Cannot touch: DOM, Three.js, Supabase, fetch. Only imports from other lib/ files or npm pure packages.

Services Layer — Network I/O
services/supabase.js services/projectShare.js services/skuAdmin.js

Can use: Supabase SDK, fetch. Cannot touch: DOM elements, Three.js directly.

2D Viewer Layer — DOM + SVG Rendering
planCanvas.js furnitureLayer.js furnitureShapes.js furniture2dRender.js roomOverlay.js doorLayer.js toolbar.js catalogDrawer.js furnitureToolbar.js billBar.js geometryEditor.js tooltip.js shareControls.js roomAutoStage.js

Can use: DOM, SVG, lib/ functions. Cannot touch: Three.js (except glbTopDownBake which needs an offscreen renderer).

3D Viewer Layer — Three.js / WebGL
plan3dViewer.js plan3dCamera.js plan3dElevation.js plan3dGlb.js plan3dMaterials.js plan3dLighting.js plan3dInteraction.js plan3dMove.js plan3dSnapshot.js plan3dWallPaint.js

Entry Point: main.js → floorPlanViewer.js

src/main.js

viewer

Literally 3 lines. Imports initFloorPlanViewer and calls it. The function creates a single closure that holds all mutable state for the entire app's lifetime.

import { initFloorPlanViewer } from "./viewer/floorPlanViewer.js";
initFloorPlanViewer();

src/viewer/floorPlanViewer.js — The God Module

controller

Everything lives inside initFloorPlanViewer(). On startup, it:

State variables

data (rooms, walls, furniture, doors), calibrationState, selectedFurnitureId, shearlingCatalog, planCatalog, catalogIndex, designBag[], vaastuEnabled, northEdge, activeMode ("2D"/"3D"), s/tx/ty (zoom+pan)

Sub-modules created

catalogDrawer, furnitureToolbar, billBar, geometryEditor — all receive callbacks so they can mutate state and trigger re-renders without importing the controller directly

Event bindings

pointerdown/move/up on planWrap (pan, drag furniture), keydown (rotate [/], undo Ctrl+Z, delete, arrow nudge), resize (debounced), file input change

On startup

Checks URL for ?share=TOKEN (load shared project), fetches Supabase catalog, merges with presets, builds catalogIndex, mounts toolbar rows, checks if Vastu enabled

Vision AI — services/vision.js

Sends the floor plan image to an AI model and receives structured JSON describing rooms, walls, doors, windows, and detected furniture. Supports 4 providers — selected by which env var is set.

fileToImageBase64(file)

Reads File → dataURL → if image > 1920px, redraws to offscreen canvas at scale. Returns {imageBase64, mimeType}. Size limiting prevents API token overload.

analyzeFloorPlan(base64, mime)

Routes to active provider: Kimi (VITE_KIMI_API_KEY), Gemini (VITE_GEMINI_API_KEY), LM Studio (local Flask proxy at /api/analyze), or remote proxy (VITE_ANALYZE_API). Returns parsed JSON.

visionPrompt.js

Contains the system prompt — tells the AI to return exact JSON schema with rooms[], walls[], doors[], calibration, furniture[]. One source of truth for what the AI should output.

jsonRepair.js

AI responses are often truncated or have mismatched brackets. Attempts to fix common patterns: unclosed arrays, trailing commas, missing closing braces.

analysisValidation.js

After JSON repair, validates the shape: checks rooms[] exists and has polygon arrays, walls have {from, to} points, etc. Throws with a human-readable error if invalid.

Coordinate System

The most fundamental concept in the app. Everything is stored in normalized 0-1 space relative to the image dimensions.

lib/calibration.js
lib

Problem: The AI gives room polygon coords but not real-world scale. Solution: User draws a calibration segment on a known-length wall. resolveCalibration(calibration, imgW, imgH) computes mmPerPixel by averaging across all calibration segments. This becomes calibrationState in the controller — passed as ctx.mmPerPixel everywhere furniture needs real sizing.

lib/coordinates.js
lib

Problem: The <img> uses object-fit:contain so letterbox bars exist. A click at pixel (200,150) on screen is NOT necessarily at 20% across the image. getRenderedContentRect(img) computes the actual rendered area. clientToNormalized(x,y,img) does the letterbox-aware conversion. normToWorld(nx,ny,matrix) converts to Three.js world space.

services/supabase.js
services

Singleton Supabase client. Reads VITE_SUPABASE_URL + VITE_SUPABASE_ANON_KEY (or Flask-injected window.__SUPABASE_URL__). Key exports: fetchShearlingCatalog(), fetchPlanCatalog(), uploadPlanRaster(file, path), resolveCatalogImageUrl(row). The shearling_catalog table is anon read-only (RLS policy).

lib/catalog.js
lib

The adapter layer. Supabase rows have messy column names with spaces. catalogEntryFromSkuRow(row, urlResolver) normalises them into a clean canonical shape every other module relies on. Also parses sofa colors, dimensions, and rich icon IDs. createCatalogIndex(entries) builds a fast lookup map.

lib/catalogSizing.js
lib

Answers "how big is this furniture on this plan?". Key: applyCatalogSkuToItem(item, row, ctx) — writes item.scale, item.catalogWidthMm, item.rich_icon, item.sofaParams from the catalog row + calibration context. Also: isSofaCatalogRow(), isChairCatalogRow(), createFurnitureNearItem().

lib/sofaColors.js
lib

Sofa upholstery colors. SOFA_COLOR_OPTIONS = array of {id, label, hex}. getCatalogRowColours(row) extracts available colors from a catalog entry. sofaColorLabel(id) returns display name. parseCatalogColourText(text) parses raw color text like "Cream, Grey" into color IDs.

Furniture Item Lifecycle

A FurnitureItem is a plain JS object in data.furniture[]. It's born in furnitureItem.create(), grown by applyCatalogSkuToItem(), queried by the module, serialized by planMoat.serializeFurnitureItem().

FurnitureItem shape

{
  id: "f_abc123",          // random ID assigned at create()
  catalogId: "SKU-001",   // links to CatalogEntry
  type: "sofa",            // furniture type string
  x: 0.42,                 // normalized position (0-1)
  y: 0.61,                 // normalized position (0-1)
  rotationDeg: 90,         // rotation in degrees
  scale: 0.12,             // width as fraction of plan width
  catalogWidthMm: 2200,    // real-world width in mm
  catalogDepthMm: 900,     // real-world depth in mm
  rich_icon: "sofa-3s",    // which SVG shape to draw
  sofaParams: {...},       // parsed sofa configuration
  sofaColorOverride: "grey", // per-instance color
  stageSource: "auto",     // "auto" or "manual"
  vaastuAdjusted: true,    // was Vastu snap applied?
  zIndex: 0,               // draw order on canvas
  roomId: "room-1"         // which room it belongs to
}
lib/furnitureItem.js
lib

create(opts) — birth with defaults (random ID, center position). isSofa(item, entry) — checks type string then catalog entry. isColorable(item, entry) — can show color picker? resolveColorId(item, entry) — active color from override → sofaParams → catalog defaults. describe(item, entry) — returns {label, colorName} for AI photoreal prompt.

lib/furnitureBounds.js
lib

furnitureHalfExtents(item) — returns {hw, hd} in normalized units based on item.scale. constrainFurnitureMove(item, rooms, data) — runs point-in-polygon check, nudges item until it's inside a room polygon. clampPlanBounds(item) — fallback clamp to 0-1 when no room exists.

lib/wallSnap.js
lib

On drag-drop near a wall: finds nearest wall segment, computes perpendicular offset, moves item so its edge is flush with the wall. Also rotates item to face into the room (away from wall). Called in floorPlanViewer on pointerup after furniture drag.

viewer/furnitureSelection.js
viewer

duplicateFurnitureItems(items) — creates copies of selected items with a small positional offset. selectionScreenRect(item, img) — computes bounding box in screen pixels for positioning the floating toolbar above the selected piece.

Geometry System

lib/geometry.js
lib

Pure math, zero dependencies. pointInPolygon(x,y,poly) — ray casting algorithm. Used everywhere: "is this click inside this room?", "is furniture inside boundary?". polygonArea(poly) — Shoelace formula. polygonBBox(poly) — min/max bounding box. polygonCentroid(poly) — centroid via cross-product formula (works for L-shapes).

viewer/planTools.js
viewer

Higher-level geometry used by both geometryEditor and plan3dViewer. createRoomFromPreset(), createWallFromPoints(), pickWallAtNorm() — finds which wall the user clicked. computeMeasure() — distance in real units. resolveWallSegmentColor() / setWallSegmentColor() — wall paint color stored per-wall-segment.

viewer/geometryEditor.js
viewer

Interactive room/wall drawing. Receives data, plan, callbacks via dependency injection (not global). Internal tool modes: view, drawRoom, vertexEdit, drawWall, setScale, measure. Uses undoStack — pushes snapshot before each mutation. Ctrl+Z pops and restores. Created once by floorPlanViewer, persists for app lifetime.

lib/undoStack.js
lib

Ring buffer, max 50 entries. push(snapshot) adds deep copy of data. pop() returns last snapshot. canUndo() checks if non-empty. Used only by geometryEditor. Simple and intentionally minimal.

Vastu Placement System

Pure logic. No DOM. Maps furniture types to compass zones based on user-set northEdge. Reference: docs/vastu-rules.md.

viewer

Main 2D render function. Converts normalized polygon coords → SVG pixel coords using image natural dimensions. Colors rooms by type: kitchen=#fffde7, bedroom=#e8f0fe, bathroom=#e0f7fa, living=#f3e5f5. Centroid calculation uses proper Shoelace formula so labels sit in the visual center of irregular rooms.

viewer

Special case: when a furniture item has a .glb model, this creates an offscreen Three.js renderer, loads the model, positions camera directly above, renders one frame, captures as PNG dataURL. That PNG becomes the 2D icon. Called once per GLB type, result cached in catalog entry.

UI Components

toolbar.js — Top Toolbar

Two rows of buttons mounted into #toolbar.

mountFileToolbar(container, handlers) — Row 1: Open image, Try demo, Upload plan (Supabase), Save, Load, Catalog, +, −, Reset, Analyze LLM, 2D View, Realistic 3D. Returns references so floorPlanViewer can set active states.

mountGeometryToolbar(container, handlers) — Row 2: Geometry group label + mode buttons: Set Scale, Measure, Draw Room, Edit Vertices, Draw Wall. Only one can be active at a time.

Imports FLOORING_OPTIONS and ROOM_PRESETS from planTools.js for the room preset dropdown.

catalogDrawer.js — Catalog Side Panel

Slide-in panel triggered by "Catalog" button. Receives setCatalogRows(rows) call from floorPlanViewer after Supabase fetch.

Cards: Each catalog entry gets a card with: image or SVG icon (via furniture2dRender.js), product name, dimensions, price, "Add to plan" button.

Search: Text input filters by name/category. Category filter buttons (All, Seating, Tables, Storage, etc.).

Favorites: Heart toggle per item, stored in localStorage["fpv:favorites:v1"]. Favorite items shown first.

Gallery tab: Calls listPublished() from projectShare.js — shows published projects from Supabase.

When "Add to plan" clicked → fires onAddItem(catalogEntry) callback to floorPlanViewer.

furnitureToolbar.js — Floating Action Bar

Appears when user clicks a furniture piece in 2D view. Positioned near the selected item using selectionScreenRect().

Actions: Add to bag (→ designBag), Rotate (5°), Replace (→ opens replace dropdown), Make copy (→ duplicateFurnitureItems()), Remove (→ delete from data.furniture).

Has a close button. Dismissed state tracked as furnitureToolbarDismissed — prevents re-showing until user selects a new item. suppressToolbarReshowUntil timestamp prevents accidental reshow after close.

Fires all actions through the callbacks.onAction(actionId) interface to floorPlanViewer.

shareControls.js — Share + Publish

Mounts "Share link" and "Publish" buttons into the toolbar.

Share link: Reads project ID from URL hash (window.location.hash). Calls ensureShareToken(projectId) → gets or creates token. Calls buildShareUrl(token) → copies to clipboard AND opens WhatsApp with wa.me/?text= link.

Publish: Prompts for title, optionally captures cover image (plan thumbnail), calls publishProject(projectId, opts) → sets published=true in Supabase, then opens gallery URL.

roomAutoStage.js — Auto Fill Rooms

autoStagePlan(data, catalog, opts) — reads room types/names and populates appropriate furniture presets:

  • Living room → sofa, armchair, coffee table, TV unit, plant
  • Bedroom → bed, wardrobe, nightstand × 2
  • Kitchen/Dining → dining table, chairs × 4
  • Bathroom → nothing (no furniture rules)

Places items at centroid with offset from room BBox. Sets stageSource: "auto" on each item.

enrichStagedFromCatalog(data, catalog) — after staging, replaces generic preset items with matching real Supabase SKUs if available (matched by category/type).

tooltip.js — Room Hover Tooltip

Simple tooltip element (#tip) shown on room hover. showRoomTooltip(el, room, position) sets text to room name/type and positions near cursor. hideTooltip(el) hides it. Called from floorPlanViewer on pointermove.

plan3dViewer.js — The 3D Orchestrator

Exports init3D(container, data, image) / dispose3D() / resize3D() / rebuildFurnitureMeshes().

On init3D(): creates scene, PerspectiveCamera, WebGLRenderer, OrbitControls. Sets up post-processing pipeline: EffectComposer → RenderPass → SSAOPass (ambient occlusion) → FXAAPass (anti-aliasing) → OutputPass. Builds room floor meshes from polygons. Calls elevation module for walls. Calls GLB loader for furniture models. Starts requestAnimationFrame loop.

Module-level globals (not class): scene, camera, renderer, controls, animFrameId, furnitureGroups[], wallSegmentMeshes[], activePlanData.

Exposes callbacks: set3DFurnitureMovedCallback(fn) — when user moves furniture in 3D, fires this so floorPlanViewer can sync the 2D view. set3DFurnitureSelectionSyncCallback(fn) — syncs selection between 2D and 3D.

plan3dCamera.js — Camera Math

flyToView(camera, controls, target, duration) — smooth animated camera move using lerp over multiple animation frames. frameCamera(camera, controls, bounds) — fits entire scene in view. computeRoomBounds(room) — room's 3D bounding box. cameraMiniMapState() — returns camera position as {x,y} for the 2D minimap dot. placeCameraFromMiniMap(pos) — moves camera when user clicks minimap. flyToSideView() — positions camera at eye level for a room wall elevation view.

plan3dElevation.js — Wall Extrusion

Takes 2D wall segments and extrudes them upward to create 3D wall meshes. Default wall height: 2700mm. Stores heights per wall in ElevationMemory in localStorage so custom heights survive page refresh. loadElevationMemory(roomKey) / saveElevationMemory() — persistence API. buildRoomWallElevations() — creates the Three.js BoxGeometry meshes for each wall segment.

plan3dGlb.js — 3D Model Loader

Loads .glb files from Cloudflare R2 using Three.js GLTFLoader. createDefaultSofaInstance() — loads the demo GLB sofa model. preloadDefaultSofaGlb() — caches it before user requests 3D view (reduces first-render latency). isSofaTypeStr(type) — checks if a furniture type should use a GLB model vs procedural geometry. Handles DRACO compression via DRACOLoader.

plan3dMaterials.js — PBR Materials

Factory functions returning MeshStandardMaterial: createFabricMaterial(color) — roughness 0.9, metalness 0, soft fabric look. createFloorMaterial() — polished floor, roughness 0.3. createGlassMaterial() — transparent, roughness 0.05, metalness 0.1. createWoodLegMaterial() — warm brown, roughness 0.6. cloneWallMaterial(color) — wall surface with slight roughness. disposeMaterials(meshes) — cleanup to prevent WebGL memory leaks.

plan3dSnapshot.js — Photoreal Render

buildFurniturePrompt(furniture) — generates a precise AI prompt: "Turn this 3D interior render into a realistic photograph of the exact same room. The room contains exactly N furniture pieces — keep all of them and add no others." The count clause prevents fal-ai/flux from adding extra furniture.

triggerPhotoreal(canvas3d, furnitureDescriptions) — captures current WebGL canvas as PNG, POSTs to functions/api/photoreal.js (Cloudflare Worker). The Worker has the secret fal-ai API key. Returns a URL to the photorealistic image. Shows a modal overlay with the result.

Server Layer

app.py — Flask Dev Server
server

Runs on port 5199 (or configured port). Three jobs:
1. Serves dist/ as SPA — all non-file routes return index.html.
2. POST /api/analyze — proxies to LM Studio at localhost:1234 (CORS bypass).
3. Injects window.__SERVER_KIMI_MODEL__ etc. into HTML so frontend knows which AI provider is active.
Reads lm_studio.json + lm_studio.local.json for LM Studio URL/model — local JSON overrides env vars.

vite.config.js
server

Multi-page build: index.html, gallery.html, manufacturer.html each compiled separately. Cloudflare Workers compatibility mode enabled. R2 public base URL configured as asset prefix. Dev proxy: /api/ → Flask :5199.

wrangler.toml
server

Cloudflare Pages config. Binds R2_BUCKET = r2-shearling for the photoreal Worker to access stored models and upload renders. Sets build output dir as dist/. Defines functions/api/ as Workers.

functions/api/photoreal.js
Cloudflare Worker

Runs server-side (not in browser). Receives the 3D canvas screenshot + furniture prompt from plan3dSnapshot.js. Calls fal-ai/flux-pro/kontext with the secret API key (stored as Cloudflare secret, never exposed to browser). Returns the photorealistic image URL. Uploads result to R2.
